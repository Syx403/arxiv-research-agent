# ARA 面试演示操作

## 本机启动

先打开 Docker Desktop，等它显示运行中。终端执行：

```sh
cd /Users/richsion/Desktop/arxiv-research-agent
make start
```

浏览器打开 **http://127.0.0.1:8000/**，保持终端运行。该命令安装锁定版本的依赖、等待数据库就绪、执行兼容已有数据的迁移，再启动网页。其他电脑按 README 配置 `.env` 后，在实际克隆目录运行同一命令。

已有服务正在运行时直接打开网址。端口被占用可用 `make start PORT=8001`，然后打开对应端口；不要启动两个服务同时发起研究。Ctrl+C 停止当前网页服务，`make db-down` 停止数据库并保留数据。

## 建议展示顺序

1. 点击「新的研究」，在「思考设置」把主任务和轻量任务都选为 Low。两者都使用 DeepSeek Flash，区别是执行角色和推理配置。
2. 第一轮输入：

   > 找到 Agentless（arXiv:2407.01489v1），只基于摘要，用两句话解释研究目标。

   展示论文身份、来源和摘要简析，解释“简单发现任务先查询 arXiv 元数据”。
3. 在同一会话追问：

   > 阅读这篇论文的原文，解释它如何逐级定位需要修改的代码，再生成补丁；只讲方法，不报实验分数。

   展示历史指代、指定版本的原文获取、检索证据、生成与逐论断核验。已经读过的版本会复用索引；这应如实称为缓存复用。
4. 展开来源与「查看本轮过程」。把一个结论对应到原文片段，再解释控制器的下一步判断、停止原因和费用。让面试官看到模型决策与程序约束如何协作。

先检查左侧剩余预算。当前网页和 CLI 共用 US$2.50 累计账本及 3,000 次请求保护，新会话不重置。页面读取和历史回看不调用模型。原文分析可能需要几十秒至数分钟；不要把已有材料缓存下的单次耗时称为普遍性能。

## 演示前检查与备用入口

```sh
docker compose -f docker/docker-compose.yml ps
curl -f http://127.0.0.1:8000/api/status
```

前者应显示数据库 healthy；后者检查网页与剩余预算，不能单独证明模型 API 可用。演示前实际完成一次上述两轮查询。

- 数据库未运行：重新执行 `make start`。单独打开网页并不证明数据库仍在线。
- API 配置：发现任务需要 DeepSeek；原文阅读另外需要 OpenAI embeddings 和 Cohere Trial。密钥见本地 `.env` 或 ARA 专用 macOS Keychain 项。
- API／网络异常或预算不足：保留页面的停止原因。可以打开已保存的真实会话说明该轮记录；也可执行 `make demo` 展示明确标注为手工示例的输出结构。
- 命令行实时入口：`uv run python -m src.cli "你的论文研究问题"`。使用返回的 `--session <UUID>` 继续追问，`--json` 输出完整机器可读结果。

不要删除数据库卷或费用账本来排除问题。`make db-reset` 会删除已有数据库内容，不用于面试启动。
