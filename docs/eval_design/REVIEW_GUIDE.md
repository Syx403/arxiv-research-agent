# ARA 校准样本、评分与首批对照

2026-09-17 更新。用户已接受“程序化主评测＋开放文本小样本来源复核”、这 12 个场景的标签及首批 US$1 上限。共享运行模块与独立 Python 评测入口已实现并通过基础测试，首批固定资料对照 16/16 已完成，合计费用与未知预留 $0.682581366。标签由助手拟定、用户接受，不属于独立盲评。实现与当前限制见 [运行说明](../AGENT_RUNTIME.md)，实测见 [首轮报告](../../data/eval_outputs/stage-pilot-20260917/run/analysis.md)。

这 12 个场景共 15 轮，涉及 5 篇论文、6 个版本。用途是校准评分与暴露设计边界，不是最终测试集。部分机制与现有回归题相同，不能当作新的独立保留集；也没有用旧结果给新规则补写分数。

## 1. 请审核的 12 个场景

完整输入及标签在 JSON 中。下表集中呈现会影响设计的判断。

| ID | 用户任务 | 本题应该做到什么 | 主要检查方式 |
|---|---|---|---|
| C01 | 按完整标题找 ReWOO，只要日期和摘要 | 找到 2305.18323；首发 2023-05-23；不反复澄清 | 程序核对身份、日期、状态；摘要另复核 |
| C02 | 在三篇指定论文中筛选 2024 年首次提交者 | 仅 Agentless 匹配；不能把 LLMCompiler 的 2024 年修订当首发 | 封闭候选池的 ID、时间约束与误选检查 |
| C03 | 从 LLMCompiler/ReWOO/GQA 中按“工具依赖并行调度”匹配度排序 | LLMCompiler 最直接；ReWOO 相关；GQA 面向模型内部注意力，不能满足该目标 | 人先确认分级，程序算 nDCG@3；解释仍复核 |
| C04 | 空会话中要求“继续深入第二篇” | 先索要论文身份或列表，不猜测、不盲搜 | 路由、澄清对象、外部请求数 |
| C05 | 先说降低 Agent 成本，再明确为工具等待时间 | 只问影响方向的关键问题；下一轮直接承接并选择 LLMCompiler | 两轮路由、目标和约束状态；澄清文字抽查 |
| C06 | ReWOO/GQA 按首发倒序展示，再追问第二篇 | 顺序正确；深入 GQA；12 个 Q 分 3 组得到 3 个 K、3 个 V、每组 4 个 Q | 列表顺序、指代、结构化数字及证据版本 |
| C07 | 先限定 2023 年工具论文，再换成 Mixtral 且取消年份 | 清除旧约束；说明每层从 8 个 FFN 专家中选 2 个，按路由权重合并 | 会话状态与结构化事实；解释抽查 |
| C08 | 严格读 Agentless v1 的阶段、定位和补丁选择 | 顶层定位/修复两阶段；定位有三个子步骤；过滤错误并按归一化补丁投票 | 版本、列表和枚举事实；语义边界复核 |
| C09 | 用 LLMCompiler 解释 A/B 独立、C 依赖两者 | A→C、B→C；A/B 可并行，C 等依赖结果；替换参数占位符 | 边集合、启动条件与证据位置 |
| C10 | ReWOO 是否完全不使用 observation | 初始 Planner 不读真实观察；Worker 获取、Solver 使用观察；解释省提示原因 | 固定布尔事实＋解释的来源复核 |
| C11 | 明确要求读原文，但注入全文全部不可用的环境 | 保留正确身份，诚实返回证据不可得；不伪造“已验证” | 隔离故障注入、停止原因、无虚构证据 |
| C12 | 综合 ReWOO/LLMCompiler 给原型与实验建议 | 机制准确，事实与工程推断分开，不承诺固定收益 | 程序查来源结构；内容按固定 rubric 复核 |

来源已经逐项查阅：[ReWOO §2.1–2.3](https://arxiv.org/html/2305.18323v1)、[LLMCompiler §3](https://arxiv.org/html/2312.04511v3)、[GQA §2.2](https://arxiv.org/html/2305.13245v3)、[Agentless v1 §2](https://arxiv.org/html/2407.01489v1)、[Agentless v2 §3](https://arxiv.org/html/2407.01489v2)、[Mixtral §2](https://arxiv.org/html/2401.04088v1)。日期根据对应 arXiv 提交历史。首批 C03/C08/C09/C10 使用的四份指定版本元数据、解析/向量索引标识和内容指纹已经保存；执行会验证数据库索引内容未变。该快照依赖现有数据库，并非可以脱离数据库独立重建全文的完整归档。

用户已接受以下三项判断：

1. C03 的排序只针对“依赖感知的工具并行调度”这个优先目标。ReWOO 得较低等级不代表它不能表达依赖，也不代表整体较差。采用等级 3/1/0；开放搜索不沿用这个封闭池的满分标准。2026-09-17 新增 v3 明确 ID 版本：原题仅写 GQA 缩写，不能排除对另一篇 GQA 工作的指代。新题 `c03-explicit-mechanism-ranking` 明确指定三篇原文及版本，原文事实和排序等级不变。旧题、澄清输出及原评分完整保留，不能通过回改旧标签制造通过率；新旧输入的结果分开报告。
2. C08 必须尊重指定版本和层级：v1 顶层两阶段，但包含补丁检查；不能把“三个定位步骤”误当“三个顶层阶段”。v2 的阶段划分不替代 v1。
3. C11 中回答恰好符合常识仍不算完成原文核验。系统正确地报告材料不可用，可以通过“故障处理”测试；这不表示它完成了用户的内容任务。两种成功分开统计。

## 2. 主表必须能读懂，也能追溯

不把所有数值揉成一个总分。每个 profile 的主表至少列出：场景数/轮数、程序合同通过数、澄清/路由正确率、参考论文覆盖、固定事实正确率、引用位置有效率、运行失败数、P50/P95 延迟、实际估算费用、输入缓存命中率。内容复核单列“已复核数、通过数、待复核数”，不能显示虚假的满分。

| 指标 | 明确计算方式与适用范围 |
|---|---|
| 路由正确率 | 正确路由轮数 / 已执行且有路由标注轮数。澄清题也可通过；未到达路由的运行失败计该指标失败并另报原因。 |
| Hit@k / MRR | 精确论文题：前 k 条存在目标即命中；MRR 为目标首个排名倒数的均值，没找到计 0。身份匹配与版本匹配分开。 |
| 参考覆盖率@k | 找到的必需参考论文数 / 已标注必需参考数。对开放题只能叫“参考覆盖率”，不是对全部 arXiv 的召回率。 |
| P@k | 仅用于标注充分的候选池。前 k 个位置的合格结果数 / k，缺少位置计 0；另报结果数量，避免只返回一篇就得高分。 |
| nDCG@k | DCG = Σ(2^grade−1)/log2(rank+1)，除以同候选池的理想 DCG。C03 用 k=3、暂定 3/1/0；全零标注为 N/A。未标注的开放论文不自动给 0。 |
| 固定事实正确率 | 正确的必需事实槽位 / 全部适用必需槽位；缺项、冲突、多值且含错误值均计错。另报已填写槽位比例，不能跳过难题提高成绩。 |
| 关系正确性 | C09 的边集合按无序集合比对；不得只命中 A→C 就漏掉 B→C，反向边也是错误。数值、集合、阶段顺序使用相应类型比较。 |
| 引用位置有效率 | 能在冻结来源中定位、身份与版本一致的引用 / 输出引用总数。要求引用却没有引用时，本题引用门槛失败；不能把 0/0 显示成 100%。它不等于论断被来源支持。 |
| 程序合同通过 | 本轮所有必要程序条件通过且无严重禁止行为。C12 只称结构合同通过，不称解释正确。内容任务完成、澄清正确、故障处理正确分类型报告。 |
| 场景通过 | 同一场景所有约定轮次的合同通过。任一前序失败导致后续无法运行，后续标 blocked；整场景不通过，不删除该场景。 |
| 输入缓存命中率 | Σprovider_reported_hit_tokens / Σprompt_tokens。提供方未返回数据时报告缺失覆盖率，不能按 0 猜测。应用缓存另算。 |
| 费用与延迟 | 所有尝试、重试、失败费用计入；未结算费用单列。P50/P95 明确样本数、超时数；完成响应延迟与所有终止耗时分开，小样本不夸大分位数结论。 |

缺失标注不当作模型失败；评分器异常不能把样本静默移出表，标 error 并报告评分覆盖率。未执行题列 not_run，不能作为已执行成功或失败；预定批次完成率另报。场景数与轮数分别给出，不能把一条三轮对话当三个独立样本计算置信程度。

更新：已接受自然语言/结构化两组分开。`natural_cases_v5.json` 保留原始问题，自由事实另行复核；`structured_cases_v5.json` 通过公开 `AgentRequest.response_fields` 请求明确类型的值。生成节点直接产出值和解释，程序用同一数据渲染表格，经原文核验后交付并程序评分，不再事后猜属性名。正确答案仍只在评分器；无额外提取/评分 LLM。旧 v4 试验与分数保留。实现和限制见 [STRUCTURED_RESULTS.md](STRUCTURED_RESULTS.md)。

人工不需要逐轮检查所有消融：先审核这些标签和严重错误；实验期间优先复核程序结果变化、解释冲突及新失败，再做小比例抽查。最终配置对约定的开放回答作来源复核。若使用 LLM 辅助复核，固定独立评分提示/版本、提供原文、单列费用，不把 ARA 自身 verifier 的结论当外部成绩。

## 3. 预备比较的模型分工

Main、Fast 都请求 deepseek-flash；是逻辑角色而非两个型号。旧基线保存实际阶段设置，不能只记录 UI 的 Low/High。以下四个 profile 已实现，完成一次小样本对照；尚未选定最终配置。

| 阶段 | A 当前行为基线 | B 语义全 Low | C 关键阶段 High | D 广泛 High |
|---|---|---|---|---|
| 意图、澄清、上下文需求解析 | 保存实际 Low/强制覆盖 | Main / Low | Main / High | Main / High |
| 已明确需求的检索式写作/改写 | 保存实际非思考调用 | Fast / Low | Fast / Low | Fast / Low |
| 候选机制匹配、条件重审 | 保存实际设置 | Main / Low | Main / High | Main / High |
| 原文片段相关性判断/选句 | 保存实际非思考调用 | Main / Low | Main / Low | Main / High |
| 证据充分性 | 保存实际非思考调用 | Main / Low | Main / High | Main / High |
| 答案生成、范围与覆盖检查 | 保存实际 Low/非思考设置 | Main / Low | Main / Low | Main / High |
| 事实核验、专项核查、语义修复 | 保存实际 Low/非思考设置 | Main / Low | Main / High | Main / High |
| 纯格式修复 | 保留现状用于比较 | 优先程序；确需模型时 Fast 非思考 | 同 B | 同 B |
| 身份/版本/预算/停止/去重控制 | 程序 | 程序 | 程序 | 程序 |

第一步先看 C 是否相对 A 有值得付出的收益，不预先承诺 D 最优。A/B 比较启用语义思考的影响，B/C 比较关键组档位，C/D 比较扩大 High 的增量。先做配置包的效果/成本比较，再按出现差异的节点消融；不能仅据组间差异就声称某个单独节点贡献了全部收益。

若沿用 Low=2048 / High=8192 的推理余量，这是“档位＋输出容量”的组合对比。后续要隔离档位本身，需另跑总输出上限固定的小对照；提示词、上下文策略、努力程度不能同时改变后归因于 High。

## 4. 成本、上下文与缓存如何进入实验

先提取现有 LangGraph 的共同运行入口，保持旧 UI 可用；建立 run/turn 级费用归属，再接独立评测脚本。每轮保留目标、明确约束及来源轮次、展示论文顺序/版本、选中对象和待澄清项；按节点提供必要材料及近期原文消息。公共论文材料缓存共享，会话状态隔离。与截取整段历史比较时要单独成组，不能把上下文改造的收益混为模型档位收益。

模型质量对照复用同一版本论文与查询资料快照，绕过应用层模型结果缓存，避免拿旧答案充当新档位结果。最新论文发现能力另用真实联网组，不把注入固定候选池的成绩说成搜索能力。资料缓存冷/热的耗时成本单独跑；固定资料组也必须注明使用的快照和解析/向量配置。

提供方 prompt cache 自动、尽力命中，不能保证每组同样热或完全冷。稳定的系统指令/Schema 放前面，动态问题和证据放后面；不为了缓存填充无关 token。交替运行 profile，记录实际输入命中/未命中 token、输出及可取得的推理 token；推理 token 已含在 completion 中时不能重复计费。应用模型结果缓存和资料缓存另有各自命中字段。

建议首个模型筛选矩阵：C03/C08/C09/C10 四个单轮原文任务 × A/B/C/D 四组 = 16 次 Agent 运行。先做其中 C09/C10 × A/C 的 4 次；验证计费、结果协议和评分正常后继续其余 12 次，同代码/材料/设置下复用先前 4 次。每格先一次只作筛选；最终候选在关键题至少重复 3 次，再扩到完整约定验收，不能把首轮一次结果当稳定胜出。

历史参照取自 data/eval_outputs/research-generalization-20260917/acceptance-v1/summary.json 及其 21 轮轨迹：193 次已返回 DeepSeek 用量记录，输入 639,905、输出 142,197 tokens，输入缓存命中 205,056；全部提供方已记估算增量约 $0.15361。它是旧设置/旧数据/部分缓存条件下的观测，不是新批次报价。

按历史平均每轮输入约 30,472、输出约 6,771 tokens 做压力估算，假设 16 轮输入数量不变、输入完全不命中缓存，全部按峰时价格：

| 假设 | 16 轮 DeepSeek 估算 |
|---|---:|
| 输出等于历史平均 | $0.2763 |
| 输出为历史平均的 2 倍 | $0.4063 |
| 输出为历史平均的 4 倍 | $0.6663 |

计算采用输入未命中 $0.30/M、命中 $0.006/M、输出 $1.20/M；核对日期 2026-09-17，参考 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/?push_animated=1&show_loading=0&theme=light&webview_progress_bar=1)。这里是条件估算，新增调用、额外上下文、重试都可能改变费用。还需计少量 OpenAI embedding；Cohere 只按现有 Trial 政策调用。

用户已接受首批 16 次的独立总上限 $1，保留准入预留及未知费用，不重置旧账本。相同 model 的 Main 不增加单 token 单价，High 的风险在于输出量、调用次数、超时和修复回合变化。收费前重新核对价格与剩余额度；预算不足停止并留下未完成项，不为凑齐结果偷偷提高上限。

## 5. 完成状态与下一阶段

已实现共享运行模块、阶段配置与隔离、会话状态、独立评测入口，以及公开字段的结构化回答/评分协议。当前离线回归为 520 项单元、3 项 PostgreSQL 集成（含结构化字段跨进程恢复和新轮清空）；未追加新的付费 v5 端到端运行。首轮付费对照属于历史代码/数据，不能与新任务混算。

上表仍是指标目标；实现覆盖路由、身份/版本、适用约束、去重、标注排序、来源位置、费用/耗时及严格字段匹配。自然问答、开放解释与推荐判断保留来源复核，不以内部核验结果冒充外部事实准确率。当前开发校准题尚不能用于泛化或最终档位选择。

不需要用户决定类名或文件拆分。需要参与的是：C03 的直接相关标准、C08 的版本/层级要求、C11 中证据不足时的正确行为，以及这些样本是否覆盖自己真正在意的失败。没有分歧的常规实现细节由工程实现决定。
