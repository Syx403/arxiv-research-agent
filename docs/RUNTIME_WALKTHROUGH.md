# ARA 当前架构与调试入口

当前目标：根据用户需求稳定查找 arXiv 论文，提供有来源的简单分析，并在需要时深入选定原文。系统使用一个 LangGraph 流程；新论文发现始终访问 arXiv，不依赖本地固定论文库。

## 以“找 MiniMax 最新的论文，然后解释第一篇的稀疏注意力机制”为例

1. **理解需求**：`plan_papers` 参考结构化会话状态及最近最多 4 条、合计最多 7,000 字符的对话，生成搜索问题、查询、阅读深度和条件。硬约束必须逐字来自用户。若关键对象无法消解，进入 `needs_input`，先澄清。
2. **搜索**：`control_research` 调度 `search_papers`，同时保留相关性和近期论文的发现路径。优先 arXiv API，服务故障时可回退到 arXiv 官方 HTML，记录真实来源。
3. **判断与恢复**：有新候选才调用 `assess_papers`。模型区分模型家族研究、相关机制、仅仅使用该模型的工作和数学同名词。程序在标题查询为空时放宽到标题／摘要，候选拥挤时换排序或分页；模型可建议补充关键词。查询、候选、判断次数、时间和费用都有上限。
4. **首轮交付**：直接匹配结果遵守用户要求的数量（最多 5 篇）；相关参考另列，最多 2 篇，不用来凑数。概念方案是否直接匹配与是否有实验证据分别记录。解释只基于所示摘要原句。“最新”在各匹配组内按已确认的首次发表日期排列。运行到达上限而覆盖不足时明确交付部分结果，不声称相关论文不存在。
5. **追问第一篇**：根据历史结果的论文 ID 和版本消解指代。用户指定原文时直接进入获取，不重新询问推荐模型这篇值不值得读。优先读取同版本 arXiv HTML，保留数学公式的原始文本表示；HTML 不可用或无法解析时回退 PDF，记录来源与材料哈希。解析器、文本块和嵌入配置匹配时复用索引；版本更新则保留旧版本，另建新材料记录。
6. **原文 RAG**：只在本次已获取的版本中进行关键词改写、向量和全文混合检索、重排、原句选择和充分性检查。检索不到充分证据时有限重试。宽泛或比较任务允许一次相关论文扩展；单篇精读默认不扩展到别的论文。
7. **生成和核验**：聚焦回答先限制到实际所问的机制。核验时先对整段答案统一判断重复与可省略的补充，再对保留句子核验原文支持；不能把“属于同一主题”当作回答所必需。去重只能指向更早保留的说明，输出不合法则保留全部句子继续事实核验。生成和事实核验使用同一份证据，校验论文／chunk 身份、引用范围、必要条件和语义支持。草稿最多改写两次；同一草稿与证据均未变化时提前停止。可支持的内容可以部分交付；核验服务错误不会变成“原文没有该内容”。

主路由见 `src/graph/controller.py`，图结构见 `src/graph/builder.py`，论文节点见 `src/graph/nodes/papers.py`。`complete / partial / incomplete / needs_input` 分别表示完成、部分交付、无法交付、需要澄清。执行结束不等于研究完整。

## 缓存为何仍需要数据库

缓存正文与把本地论文库当作唯一发现范围是两回事。Postgres 保存材料、嵌入和运行状态。新搜索走外部 arXiv；读过的论文可按 ID、版本、处理配置复用。旧论文记录和旧 chunk ID 保留以支持历史引用，但不会混入新论文发现。新搜索的响应可以留作诊断，不用于跳过本次 HTTP 搜索。

同一版本的 HTML／PDF 可以复用；索引处理方式改变时建立新索引。向量按文本及模型配置缓存，相同文本不必重复嵌入。模型判断缓存还包含需求、上下文、候选、提示/schema 和推理配置，避免把不同问题的判断混用。

聚焦问题与整篇概览分别处理。聚焦问题按已消解的用户问题检索和验收，不能把规划器自行扩展的细节变成用户必须要求的内容。原论文中被模型标为背景、但有助于另一问的片段仍可进入证据包；不因为已有一个直接机制段落就丢弃这些互补证据。

## 核实论文中的一个说法

例如“这篇论文是否证明了任意分布下的最优性”，规划为 `verify_claim`，先执行一次指定版本的原文检索，再有界补查该版本当前索引的解析文本。补查最多读取 300 个块、24,000 token，保留章节、块和精确选句位置；复用已有材料与向量，不再次嵌入整篇论文。它不是所有精读请求的默认额外步骤。

补查可返回 `supported / contradicted / not_established / insufficient`。前两者分别要求支持证据和明确反证；没有找到证明不等于反驳了命题。只有该版本可用解析材料全部进入检查、关键材料没有明显缺失、选中证据没有被预算裁切时，限定于本次材料的 `not_established` 才可完成核实任务。长文扫描截断、原文不可用或判断服务失败仍属未完成。即使全部解析文本进入检查，也不承诺解析器完整恢复了 PDF 中每个公式或图表。

模型对补查的自由文字总结不作为技术证据注入最终回答；生成和核验只使用实际选句及程序记录的检查范围。负面结论必须在同一句中限定“本次查阅的解析文本未找到支持”，不能用后面的免责声明修饰前面的全局断言。页面的“查看本轮过程”展示实际补查范围；未纳入回答的重复句或额外说明与事实核验失败分别标注。

范围和事实核验使用统一阶段配置，范围判断失败时停止继续生成可信结论并保留已核验内容；事实核验使用本轮选定的主任务推理档位。原因来自真实反例：旧核验曾接受把 `I > a` 解释成上界的错误，新版增加了正反表述对照回归。这是一个具体修复的证据，不保证任意数学推导都能正确核验。

## 费用与基础验证

所有真实 UI 与 CLI 请求共享既有 US$2.50 账本，不重置累计花费。搜索单轮预估准入上限为 US$0.05，正文分析为 US$0.15。预算在发送前预留，失败时无法确认的计费保守保留。单元测试禁止真实 HTTP；数据库集成测试使用合成材料和嵌入，不产生付费调用。

基础测试覆盖动作选择、重复候选、澄清、非法约束、判断服务失败、版本／索引更新、并发获取、取消恢复、跨进程恢复、引用绑定和费用限制。它们用于验证系统行为；之后需要共同设计独立的论文质量评测集，才能评估真实相关性、覆盖、分析质量、延迟与成本。

页面中的 **查看本轮过程** 对应本地 `data/ui/sessions/traces/<session>/<turn>.jsonl`。检查顺序是：用户原问题 → 解析需求 → 实际查询及来源 → 候选与筛选理由 → 控制器下一步动作 → 正文版本与引用 → 停止原因。日志保留模型可见的结构化输出，不记录隐藏思维链或密钥。

## 2026-09-16 基础验收

离线回归已通过，数据库检查使用真实 PostgreSQL 和合成外部适配器；覆盖版本更新、处理配置更新、旧 chunk 保留、并发／取消和跨进程恢复。最终真实样例采用 Flash low/low：

| 场景 | 实际结果 | 单次观察耗时 |
|---|---|---|
| MiniMax 最新论文 | 找到 Sparse Attention、M2 系列、M1，并把 2026 年机制论文排在第一位 | 30.2 秒 |
| 2026 年 MoE 路由／负载均衡，只看摘要 | 返回三篇符合时间范围的论文与机制简析 | 40.5 秒 |
| 新会话中未说明对象的“这两个方案哪个好” | 请求补充对象／需求，没有搜索论文 | 2.4 秒 |
| “阅读第一篇”追问 | 解析到 2606.13392v2，复用正文索引，交付核验后的原文分析 | 22.1 秒 |

这些是单次功能检查，部分请求命中缓存，不是性能基准。最后一次精读的四处原文引用已逐一与数据库文本及字符范围对照一致。MoE 样例发生一次推理占满输出空间的截断，已有的单次非思考格式恢复成功；减少这类恢复的延迟仍是后续优化项。

这一轮开发与在线验证共新增约 US$0.0865 的预算占用（含中途失败请求的保守预留）；累计占用 US$1.3469 / US$2，余约 US$0.6531。账本未重置。这些结果不足以证明所有主题都能搜全；正式质量评测集尚待共同制定。
